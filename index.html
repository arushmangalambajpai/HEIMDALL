Question 02

Why is hardware supervision necessary?

Software bugs or hardware faults can trap processors in silent failure states.

An Autonomous Robot Freezes

A memory glitch freezes the motor controller mid-turn. Without external reset logic, the robot continues driving blindly forward.

A Satellite Stops Responding

Cosmic radiation corrupts a single register bit in orbit. Without independent hardware supervision, communication is lost permanently.

An Industrial Line Hangs

A power line transient forces a factory PLC into an infinite loop. The system continues outputting stuck control signals.

Question 03

Traditional Watchdogs vs. HEIMDALL

A traditional watchdog timer only checks if the computer is pulsing—not if its logic is sound.

Standard Approach Simple Timer WDT

|---|---|---| [Blind Reset]
  • Detects complete system freezes or software deadlocks.
  • Flaw: If code gets trapped in a loop that still resets the timer, the WDT thinks the CPU is healthy.

DUAL-CHECK SIGNAL PROTOCOL:
1. Heartbeat [ Pulse Verified OK ]

  • Checks liveness via continuous heartbeat window monitoring.
  • Issues dynamic challenge-response math queries to verify program execution paths.
Question 04

What makes HEIMDALL different?

It continuously poses two verification questions to the main CPU:

01

"Are you alive?"

Heartbeat Verification: The main CPU must issue periodic pulses to a designated hardware register window. If a pulse arrives too early or too late, HEIMDALL flags an error.

02

"Are you executing correctly?"

Challenge-Response Logic: HEIMDALL generates a pseudorandom query. The CPU must perform a specific calculation and respond within a strict time frame to prove valid control flow.

Heartbeat Timing Engine

Monitors incoming periodic hardware pulses from the primary processor. Uses dual-threshold counters to ensure timing falls within strictly predefined cycles.

What happens on fault detection? If pulse counter exceeds max timeout window, asserts hb_timeout trigger to Supervisor FSM.
